# Issues & features

Open issues and feature requests, merged from the former `docs/issues.md` and `docs/features.md` (2026-08-20) into a single sorted list. Completed or superseded items — including ones from the old files that were already resolved but hadn't been moved out yet — live in `docs/archived/archived_issues_and_features.md`.

- A row should only have sub-items if there is a sub-item that isn't filtered out. Currently completed items can cause the row to be expandable when showComplete is false, and expanding it shows nothing
- Dead code: `update_project_task_form`'s `Err(ItemError::NotFound) => ...` arm (`src/web_ui/project_tasks/handlers.rs`, the `hx-refresh` fallback after the second `get_project_item_unchecked` call) is left over from item-level recurrence, which was fully retired in Stage 10 (see root CLAUDE.md's Recurrence section) — a completed item can no longer be replaced with a fresh successor under a new id, so this arm can never actually fire anymore. Safe to delete, along with its now-stale comment; found while fixing the "completing an item returns a not found error" bug (see its resolution note in `docs/archived/archived_issues_and_features.md`), which turned out to come from a different bug entirely (not this branch).
- Multi-select: let's add a Select button that temporarily changes the UI so that the checkboxes are disabled, and items can be selected by tapping/clicking on them, highlighting the whole row in some way. Clicking the Select button also replaces itself with an action button. The batch-action button will be replaced with a dropdown on being pressed, and will include in its fetch from the server which items are selected so that the menu can actually show the available actions for those tasks. For example we should not show "set offset" unless all the tasks are sub-items of the same top-level parent, and we should not show schedule or due date unless all the tasks are top-level tasks. Should not be able to select sub-items of different parents, or a mix-of top-level and sub-items of any top-level item.
    - Would like to provide following actions, now or eventually:
        - Set Assignee (for team-project-items)
        - Set offset (for sub-tasks)
        - Set Due / Schedule dates (for top-level items)
        - Set priority
    - **Status (2026-08-29): shipped for the project Tasks list only** (`/web/projects/:project_id/tasks`, `?select=1` — `src/web_ui/project_tasks/`). Select/Cancel/Actions, and 3 of the 4 actions above (priority, due/schedule dates, assignee); a short instructions blurb shows in select mode. Simplified from the original ask in two ways, both deliberate: (1) an invalid selection isn't prevented client-side or filtered out of the Actions menu server-side — any selection can be made, and picking an action it doesn't support just surfaces an error (via the existing global error dialog) — and (2) select-mode rows are top-level-tasks-only, no sub-items shown/selectable at all (an earlier version nested them, which visually made selecting a parent look like it also selected its children, since the child rows sat inside the parent's own highlighted background).
    - Remaining/deferred (not yet started):
        - Extend the same Select/Cancel/Actions UI to the other list screens: `project_events`, `project_simple_lists`, `all_projects_tasks`, `all_projects_events`.
        - Add a feature to a task's own full page to select among *its own* sub-items (see the "Task filters should be available on task full page for its sub-items" item below for the same full-page-parity idea applied to filters) — this is what "Set offset" actually needs, since an offset selection only makes sense across sub-items sharing one parent. The backend for this already exists and is just waiting on a UI entry point: `batch_set_offset_form`/`require_same_parent_subitems`/`BatchOffsetForm` (`src/web_ui/project_tasks/handlers.rs`), reachable today only via `PUT /web/projects/:project_id/tasks/batch/offset` directly, with no menu button or dialog wired up on any screen.
