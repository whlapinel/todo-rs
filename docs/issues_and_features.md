    - **Found while scoping this (2026-08-29): `get_or_materialize_occurrence` had no guard against materializing an already-skipped (`is_exdate`) occurrence.** `record_materialized_occurrence`'s SQL upsert unconditionally sets `is_exdate = 0` when it writes an `item_id`, so calling the materialize path on a skipped occurrence would have silently un-skipped it as a side effect — bypassing `unskip_occurrence`'s cursor-safety rule (only a Task series' current cursor date can be unskipped, via a proper cursor-retreat). Nothing shipped in this pass could actually reach that path (Edit/Add sub-item are gated behind `!is_skipped` in the menu), but it was a latent trap for any future caller. Fixed by adding an explicit `is_exdate` check at the top of `get_or_materialize_occurrence` that returns `ItemError::Invalid` instead — a caller must go through `unskip_occurrence` first if it wants to reinstate a skipped occurrence. Covered by a new test, `rejects_materializing_a_skipped_occurrence`.
