- Bug found while implementing Stage 3 of `docs/calendar-day-drawer-plan.md` (2026-08-22), still open as of Stage 8's route/module rename: `render_rows`'s assigned-to-me filter in `src/web_ui/project_calendar.rs` (renamed from `project_dashboard.rs` in Stage 8 — the per-project Calendar's flat list view) is `assigned_to_any || item.assigned_to_user_id() == Some(user_id)`, with no gate for personal (non-team-backed) projects. A personal-project item never carries a `TeamAssignment` at all (confirmed in `src/domain/item.rs`/`src/storage/sqlite/mod.rs`'s row mapping), so `assigned_to_user_id()` is always `None` for one — meaning this filter silently excludes *every* item on a personal project's Calendar list by default (`assignedToAny` unchecked), unless the user manually checks "Assigned to Any" every time. The Stage 3 calendar work added the equivalent filter gated on `is_team_project` (`day_list_rows`/`build_calendar_days` in the same file) specifically to avoid repeating this bug, but `render_rows` itself was left untouched (outside that stage's scope). Fix: gate `render_rows`' filter the same way — `!is_team_project || assigned_to_any || ...`.
- Add a New-item button to the cross-project Home calendar (`templates/main_calendar/calendar_page.html`, `src/web_ui/main_calendar.rs` — renamed from `main_dashboard.rs`/`templates/main_dashboard/` in Stage 8 of `docs/calendar-day-drawer-plan.md`), mirroring the per-project calendar's `+ Task`/`+ Event` header buttons (`docs/calendar-day-drawer-plan.md` Stage 3). That plan's Confirmed design decisions section deliberately excluded this from Stage 4 ("item creation is inherently project-scoped and Home has no single natural project to create into") — the user has since said they did want one there and missed that decision during planning. Needs a design pass this plan never did: since Home isn't scoped to one project, the New button needs some way to pick which project the new item goes into (e.g. a project-picker dropdown before landing on `/tasks/new`/`/events/new`, or defaulting to the user's most-recently-active project) — not just a straight copy of the per-project version's two-link segmented control.
